**This release catches up with four dependency updates from upstream moonlight-qt, including a fix for a startup crash tied to a Windows security feature.**

## What changes

Four upstream moonlight-qt commits are merged in, all dependency-bundle updates with no source-code changes:

- **libplacebo** updated (two steps, ending at `e2972fd`).
- **FFmpeg** updated to **9.0.2**.
- **SDL** updated to build `383fb13`.
- **A fix for a Control Flow Guard (CFG) violation on startup in OpenSSL.** CFG is a Windows security
  feature. With certain Windows security settings, the previous OpenSSL build could hit a CFG
  violation and crash the app as it started. This release also disables CFG specifically for OpenSSL,
  and then fixes the violation.

None of this is a change to MoonlightVibe's own source code. All four changes are to the prebuilt
dependency bundle the build downloads, which moves from `v15` to `v18.1`. Nothing in MoonlightVibe's
own 47-file delta from upstream was touched.

## Who this affects

Everyone. The OpenSSL CFG fix addresses a real startup crash, so anyone who hit it should benefit.
FFmpeg 9.0.2 and the SDL update are routine upstream maintenance and are not expected to change
anything you notice.

## How this was checked

MoonlightVibe is a client application (Qt/C++, built for Windows and macOS). This host is headless,
and no Moonlight client has been run or streamed with on this host in this session, so that has not
been verified here.

Windows x64 and macOS both built successfully in CI before this was merged: a manual dispatch of the
sync branch, and the pull request's required checks, which also build the Linux AppImage. But nobody
has run or streamed with this build. That is a real limitation, not a formality, and it applies to
the new FFmpeg, libplacebo, SDL, and the OpenSSL change alike.

## Unchanged

No MoonlightVibe source code changed. The application's own logic, UI, and seat discovery are
exactly as they were in 6.3.5.
