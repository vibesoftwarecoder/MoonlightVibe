**This release fixes the real cause of macOS installs showing "MoonlightVibe can't be opened because it is damaged or incomplete" — confirmed working on a real Mac.**

## What was happening

Issue #13, continued from 6.3.7. The previous release's ad-hoc-signing fix did not resolve the problem — the reporter confirmed it was still "damaged" after upgrading. That ruled out the original theory (a completely unsigned app bundle) as the real cause.

## What changes

The actual bug: `app.pro` renamed the macOS build's target executable from `Moonlight` to `MoonlightVibe` back in May, but `app/Info.plist`'s `CFBundleExecutable` was never updated to match — it had been pointing at a filename that's never existed, in every release since. `macdeployqt` resolves a bundle's main executable through that same field, so it silently failed to deploy the app's Qt framework dependencies into the bundle at all. The result was a structurally incomplete app, independent of signing — which is exactly why ad-hoc signing in 6.3.7 didn't help: it correctly signed an already-broken bundle.

Fixed by updating `CFBundleExecutable` to match.

## Who this affects

Anyone installing MoonlightVibe on macOS — this bug has been present in every fork release since May, not just recent ones.

## How this was checked

Before this release, a CI-built test artifact (not an official release) was built from the fix and handed to the original reporter directly, specifically because the previous fix attempt had looked correct in CI and wasn't. They confirmed it: *"the build worked and i had to use the 'Open anyway' in privacy and security and it actually booted up."* That's the expected flow — a normal, bypassable Gatekeeper prompt, not "damaged." This is real-world confirmation on an actual Mac, not just a clean CI log.

## Install

Download `MoonlightVibe-mac-6.3.8.dmg` from the release, drag to Applications. On first launch, macOS will likely still show an "unidentified developer" prompt — that's expected; use right-click → Open, or System Settings → Privacy & Security → Open Anyway.
